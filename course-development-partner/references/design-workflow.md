# Educational Design Workflow

## 1. Establish collaboration

Inputs: user request, available sources, current portable state.

Actions:

1. Identify teaching use, audience, artifact scope, and desired output.
2. Offer Studio, Guided, or Rapid mode.
3. Determine whether the task creates, revises, reviews, or adapts.
4. Create or update the course-design brief.
5. Identify the next pivotal question.

Output: working brief and Confirmed/Assumed/Open lists.

## 2. Inspect context

Classify source material as:

- authoritative requirement;
- professor-approved decision;
- reusable legacy material;
- provisional material;
- conflicting or outdated material;
- missing information.

Extract discipline, course level, student population, prerequisites, delivery mode, class size, duration, staffing, technology, accessibility, grading, policy, and format constraints. Ask the instructor only to resolve consequential uncertainty.

Output: source inventory and course-context summary.

## 3. Establish alignment

1. Extract or draft observable learning outcomes.
2. Identify intended cognitive demand.
3. Define acceptable evidence of learning.
4. Map activities and supports to that evidence.
5. Map feedback and assessment to each outcome.
6. Detect unsupported outcomes, orphan activities, and over-assessment.

Use `assets/alignment-map.md`.

Output: accepted alignment map.

## 4. Diagnose the challenge

Identify:

- prerequisites students must activate;
- common misconceptions and errors;
- conceptual, procedural, computational, communication, or transfer difficulty;
- where students must choose, interpret, compare, justify, diagnose, design, or transfer;
- supports students need now and supports that should later be removed.

Output: learning-challenge profile with scaffold depth.

## 5. Design the sequence

Draft tasks before polished prose. Use only steps that advance learning. A useful progression is:

1. activate prerequisite knowledge;
2. recognize or explain the concept;
3. apply it in a familiar case;
4. compare cases, approaches, or models;
5. diagnose an error or misconception;
6. decide under realistic constraints;
7. justify, transfer, or extend.

For each step, record purpose, expected evidence, time, student action, instructor/TA move, likely error, and feedback. Include opening, active work, checkpoints, debrief, closure, and contingency.

Output: accepted sequence map or lesson storyboard.

## 6. Add authentic context

Use context only when it changes or clarifies disciplinary reasoning. Define:

- credible setting;
- student role or stakeholder;
- professional decision;
- relevant concept or model;
- evidence or data;
- assumptions and simplifications;
- expected interpretation;
- reason the context improves learning.

Verify discipline-specific and time-sensitive facts. Avoid irrelevant detail, stereotypes, contrived urgency, and fake precision.

Use `assets/context-brief.md`.

Output: accepted context brief.

## 7. Produce the artifact family

Create only what the teaching use needs. Consider:

- student-facing artifact;
- instructor guide;
- solution or exemplar;
- rubric or feedback guide;
- accessibility alternatives;
- sources and verification notes.

Keep terminology, notation, data, assumptions, difficulty, outcomes, and scoring logic synchronized. Use the artifact manifest to track status.

Output: linked draft artifact family.

## 8. Validate and package

Run separate passes for:

1. disciplinary and technical correctness;
2. constructive alignment;
3. scaffolding and readiness;
4. active-learning feasibility;
5. accessibility, inclusion, and clarity;
6. assessment integrity and fairness;
7. file and rendering integrity.

Classify issues as Blocker, Important, or Polish. Correct unambiguous blockers. Request instructor direction when a change alters intent or grading.

Package with clear names, student/instructor labels, editable sources, rendered previews when supported, implementation notes, timing, materials, contingencies, last-reviewed date, provenance, and open issues.

Output: teaching-ready bundle and updated artifact manifest.

## 9. Reflect and iterate

After teaching, ask the instructor to record:

- observed understanding and misconceptions;
- timing and participation;
- useful and ineffective prompts;
- performance or feedback evidence;
- supported, unsupported, and uncertain claims;
- revisions for next use.

Do not infer learning gains from satisfaction or anecdote alone. Produce a revision memo and update the design log.
